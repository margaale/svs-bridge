How it works

The RetroTINK 4K cannot tell Cruller when the switch changes input, so the bridge does. Pick the Cruller connected to the RetroTINK this switch feeds: the bridge sends it the active input on every change, when it finds it (also after it restarts) and every minute. Cruller then applies only the game profile of the console on screen.
A Cruller takes reports from the first bridge that sends them. To move it to another bridge, press Unpair in its Cruller tab. Crullers announce themselves over mDNS as _rt4k._tcp; the bridge remembers the one you pick by its id, so its address may change.

    Bridge firmware

    –
    The bridge downloads the firmware straight from GitHub, checks it (ESP32-S3, project svs_bridge, checksum) and restarts into it. It keeps the new version only once it reconnects to the Wi-Fi; otherwise it goes back to the current one by itself.
    Running–Release notesgithub.com/margaale/svs-bridge

    Serial console clients (RFC 2217)

    –
    No client connected. Connect to rfc2217://svs-bridge.local:2217 (e.g. pyserial): clients see what the SVS says, and the lines they send go to the SVS.
    What these clients send reaches the SVS only with the RetroTINK's HD-15 unplugged: the SVS shares that line.
    Each connection, what it sends and why a line was not passed on also go to the SVS tab's serial log.

    API token

    Home Assistant discovers the bridge on your network by itself. Paste this token when adding it, so it can read the SVS state.
    Regenerating revokes the old token: update it in Home Assistant afterwards.
